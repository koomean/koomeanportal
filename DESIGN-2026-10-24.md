# Koo Mean Portal — connected workspace, 24 October 2026

Brief: soften the whole current interface, add useful motion, retain the existing structure, black canvas and blue/cyan identity, remember user choices, and protect performance/security. Scope: koomean.com only.

Palette: charcoal canvas #14181d; panel #1b2027; raised surface #242f3b; text #edf3f8; muted #a9bac9; sky accent #83d3fa (light accent #24639c). Blue is an interaction signal and localized hero detail, not a full-page tint. Keep existing local IBM Plex Sans Thai for Thai and Latin, with real keyboard shortcuts the only monospace content. Headlines 40–64px, body 15–16px, controls 13–14px.

Layout: familiar header → hero/video → social rail → app tools and catalog → footer. Left-aligned copy, deliberate spacing; generous large surfaces and tighter controls. Hero gets a clear link to the app collection and quieter contact action. The right side keeps the existing animated Koo Mean tile, rather than adding an unrelated illustration or generic statistics. The hero keeps a clear route into the application collection; playback preferences are available in Settings. App logos lead the card hierarchy; metadata and actions are quieter. Settings, account, login, help and admin inherit the same surface/spacing/control system.

Motion: one short hero copy entrance, then motion driven by user intent: nav/segment selection, card hover/press, favorite confirmation, view changes and dialogs. Transform/opacity for animated movement. No parallax, cursor tracking, scroll listeners, animated gradients, or extra framework. Existing autoplay and Settings playback choices stay, reduced motion stays static, hidden/offscreen video/rail still stop, preferences remain saved. Rapid interactions cancel previous animation rather than queue effects. A page-level motion setting will only be added if it can cleanly cover decorative motion without changing the existing independent rail/video choices.

Critique: a stronger blue accent plus identical pill cards would repeat a generic app dashboard. Revised direction keeps charcoal and varied radius hierarchy (hero 30px, cards 20px, controls 12px) and puts the characteristic brand tile in the hero. Remove excess outlined nesting instead of adding glow to every element. Preserve useful card boundaries for scanning real app links. Avoid staggered entrance on every render/search and avoid hiding content while waiting for JS.

References read: local frontend-design skill; Vercel web-design-guidelines and current Web Interface Guidelines; web.dev high-performance CSS animations. No online script or runtime design package is needed.

## Implemented and verified

The original header/hero/social rail/catalog order is preserved. Added a catalog shortcut, softer surface/control hierarchy across the main page and dialogs, and shared interaction motion. `interfaceMotion` is a typed boolean saved in `koomean_portal_prefs_v3`, defaulting to true for earlier preferences. It controls decorative feedback independently from the saved social-rail/video choices. OS reduced motion and data saver suppress the effects without overwriting user intent. Finite WAAPI effects replace earlier effects on the same element; no animation queue, search entrance, scroll observer or animation library is added. Touch editors retain 16px text. Native select dimensions remain 44px.

Security: existing strict CSP, URL/color validation, escaping, local icon sprite, memory-only token storage, server-response-derived admin UI, race guards and modal inert/focus isolation are preserved. Unused Google Fonts connection hints were removed; fonts and interface icon sprites remain self-hosted. `npm ci --ignore-scripts` audited all 6 packages with zero known vulnerabilities. Tests use synthetic authenticated fixtures; they do not bypass or independently audit the live Worker authorization.

Validation: 97 Chrome browser checks; 33 WebKit checks for iPad portrait/landscape and iPhone; 19 security, maintenance and language unit checks; domain/asset guard. New checks cover saved effect choices, independent rail autoplay, rapid view changes, cancelling effects, reduced motion/data saver, expanded dialog state, catalog shortcut and 16px touch text. Visual checks cover 280–1440px responsiveness, grid/list/compact, Thai/English, dark/light, settings/account/admin/help/commands and long content.

## Performance comparison

Three alternating cold-cache runs per build, 390×844 touch, CPU 4×, RTT 150ms, download 1.6Mbps, upload 0.8Mbps, gzip assets, same replayed public API with 100ms response delay. This is a controlled localhost lab comparison, not production field Core Web Vitals. Small final English copy changes do not materially affect these measurements.

| Median | Before | After |
| --- | ---: | ---: |
| Largest contentful paint | 960ms | 1008ms |
| Cumulative layout shift | 0.0158 | 0.0017 |
| Full load event | 1859ms | 1893ms |
| Search to visible results | 159ms | 171ms |

The refresh adds about 3.7KB transferred (0.85%) with the same 20 resources and no new runtime dependency, downloaded font, bitmap or video. It trades roughly 48ms of lab LCP for the full visual refresh while reducing measured layout shift. Do not present this as a blanket speed improvement or a field INP measurement.
