# Koo Mean Portal redesign

The Portal is a practical entrance to Koo Mean services. The design brings the application catalog forward and gives account, favorites, preferences, help and administration their own addresses. It keeps the shared API, permission checks and memory-only Google identity.

## Design direction

Palette: workspace paper `#f6f8fc`, white surface `#ffffff`, ink `#192b43`, Koo Mean blue `#245beb`, hero blue `#204fd5`, availability green `#1a7c67`. The dark theme uses blue slate surfaces rather than pure black. Existing preferences continue to select light, dark or system appearance.

Typography: locally hosted IBM Plex Sans Thai for both Thai and English, with a restrained scale from 10–14px supporting copy to 32–47px hero type. Font licenses remain included.

Layout: persistent left navigation on desktop; a disclosure menu on smaller screens. The workspace header stays quiet. The blue portal-window illustration is the one expressive gesture. Social links have a light horizontal rhythm; app entries use consistent, readable cards, with list and compact choices preserved.

```
Navigation | Workspace header
           | Welcome + portal window
           | Social links
           | Search, filters, application catalog
           | Footer
```

Review against brief: a generic landing-page hero with statistics would not help people launch an app. The design uses the existing four-pane Koo Mean mark as a portal window instead, gives navigation priority, and adds real page addresses. There are no fabricated usage statistics or service-health claims.

## Page contract

`/`, `/apps/`, `/favorites/`, `/account/`, `/settings/`, `/help/`, `/admin/` are explicit routes. Internal navigation shares the shell so Google tokens stay in tab memory. Direct reload still requires sign-in, as before. GitHub Pages receives real route directories and a custom `404.html`. Unknown paths retain their URL and receive HTTP 404, with root-relative assets. Missing search results are a catalog empty state, distinct from a missing page.

Login, registration, command search and logo selection remain focused dialogs. Account and admin routes show guards until server-verified identity permits access. This release changes the Portal frontend only.
